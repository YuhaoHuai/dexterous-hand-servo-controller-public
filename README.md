# DS939MG 舵机控制（PlatformIO）

依据 `Code copy/TestDrvice/platformio.ini`，使用 Seeed XIAO ESP32S3；原工程文件未修改。

## 使用

1. 在 VS Code 中用 PlatformIO 打开本文件所在文件夹，点击 Build。`platformio.ini` 已配置依赖和 115200 波特率。
2. 确认接线后再上传：D4/GPIO5 → SDA，D5/GPIO6 → SCL。PCA9685 逻辑 VCC 接 3.3V，舵机 V+ 使用独立且满足负载的电源；主控、驱动板和舵机电源必须共地。确认实物驱动板的 V+ 额定电压。
3. 第一块地址保留 `0x40`，第二块保留 `0x60`。第二块需要与地址焊盘配置一致（通常 A5 闭合、其余断开），不能两块都保持出厂 `0x40`。
4. 第一块通道 0～11 对应舵机 0～11；第二块通道 0～11 对应舵机 12～23。每块余下 4 个通道不用，初始化时也关闭。
5. 串口监视器使用 115200，每条命令以换行 LF 结束；CRLF 也支持。初始化后关闭 PWM，不自动让舵机归中。若错过启动日志，发送 `help`。

先只接一个卸载舵机，卸下拉线/连杆，并确认 1500µs 附近不会碰撞。逐条发送，观察动作后再发下一条：

```text
servo 0 1500
smooth 0 1450 1000
smooth 0 1550 1000
smooth 0 1500 1000
stop
```

首次 `servo` 指令仍可能直接跳到目标位置。没有编码器反馈，软件无法保证上电后第一次动作平滑。后续 `smooth` 也只是从最后一次成功发送的指令值插值，不保证舵机实际到位。

## Windows 图形界面

关闭 PlatformIO 串口监视器，双击 `gui/start_gui.cmd`。选择 XIAO 所在的 COM 口并点击「连接」。界面读取固件上报的两块驱动板地址和 I2C 状态，保留串口日志供排查。

单路调节可填写舵机编号、脉宽、映射角和用时。先点「设定脉宽」，再试「平滑移动」或「单路测试」。三路演示默认使用映射角 135°，控制舵机 0、1、2。需要结束动作并关闭 PWM 时点击「停止输出」。

界面使用 Python 的 Tkinter，优先使用已安装的 pySerial，也可复用 PlatformIO 环境中的 pySerial。可在终端运行 `python gui/servo_gui.py` 启动。需要单独安装串口库时运行 `python -m pip install pyserial`。

点击串口日志右侧的「指令库」，输入序列名称，每行填写一条指令，再点「保存」。下拉框可载入已保存的序列。连接串口后，点击「运行」执行编辑器中的序列。保存文件位于 `gui/command_library.json`。

```text
servo 0 1500
wait 500
smooth 0 1550 1000
wait 1000
smooth 0 1500 1000
```

`wait` 的单位为毫秒。平滑移动按设定用时等待，演示和测试等待固件的完成回执。发生错误、掉线或回执超时会中止后续步骤。「停止输出」同时取消序列并发送 `stop`。

## 关节微调

上传新版固件并重新打开 GUI，点击「关节微调」。填写关节名称、舵机编号、方向和步长，再点「保存分配」。分配保存在 `gui/joint_mapping.json`。选择已保存的一行后可以编辑，点击「新建」可添加另一项。

选中关节后，点击「＋」或「－」微调，默认每次改变 10 µs。正向的「＋」增加脉宽，反向的「＋」减少脉宽。固件从该路最后一次成功输出的脉宽计算目标，并限制在配置的脉宽范围内。首次输出时，填入该关节适合的起点脉宽并点击「设定起点」。

## 开机检测和每 3 秒检查两块驱动板

`setup()` 自动调用 `checkAndInitializeServoBoards()`，分别探测预期地址 `0x40` 和 `0x60`，再初始化响应的板，并关闭 PWM。打开 115200 串口监视器后复位主控，可查看逐板状态和总数。两块都正常时输出：

```text
Checking PCA9685 boards...
Board 1 (0x40): connected, ready, PWM off
Board 2 (0x60): connected, ready, PWM off
Servo boards: 2/2 responding, 2/2 ready
OK both servo driver boards are ready
```

未响应的板显示 `not responding` 和 I2C 错误码；有响应但初始化失败会单独报错。汇总会区分有响应的数量和初始化成功的数量。缺板或初始化失败时，其对应通道拒绝控制；已就绪的板仍可单独使用。

`loop()` 通过 `millis()` 每 3000ms 调用一次 `checkServoBoardConnections()`，输出两块板的当前响应状态和数量。周期检查只探测地址，不重新初始化、不改写 PWM，也不使用 `delay(3000)`，串口和运动更新持续执行。检查间隔可通过 `BOARD_CHECK_INTERVAL_MS` 调整。

检查失败时核对逻辑 VCC、共地、SDA/SCL 和地址焊盘。如果两块都保持默认地址 `0x40`，程序不能区分这两块板，`0x60` 检查会失败。本功能检测预期地址的 I2C 通信，不检测舵机是否接入、V+ 电源是否正常。周期检查不改变运动状态，也不自动恢复初始化；驱动板重新上电或开机时缺板后补接，请复位主控以重新初始化。

## 三路同时运动样本

串口发送 `demo`，或者发送 `demo 135` 指定映射角度。代码入口是 `demoServo012(float angle = 135.0f)`；在其他代码中调用一次 `demoServo012(135.0f);` 也可以，`loop()` 需要继续执行现有的运动和测试更新。

流程：仅将舵机 0、1、2 设到默认 1500µs 并留 500ms 准备时间，然后三路在 500ms 内同时过渡到目标，目标指令全部发送完成后保持 2000ms，最后三路在 500ms 内返回 1500µs。已初始化的舵机在准备阶段也采用 500ms 平滑过渡。上电后首次设定默认位置仍可能直接跳转。

默认映射角 135 在 1000～2300µs 范围内对应 1975µs。三路在同一更新周期调度，I2C 逐路写入存在很小的先后差异。整个流程不阻塞串口，发送 `stop` 可取消。返回 1500µs 后继续保持 PWM。

## 命令

| 命令 | 含义 |
| --- | --- |
| `servo 0 1500` | 舵机 0 立即设置 1500µs |
| `angle 0 90` | 将 0～180 的输入线性映射到该路配置范围；不是实测机械角度 |
| `smooth 0 1550 1000` | 从最后一次指令值在 1000ms 内过渡到 1550µs；需要先发送初始脉宽 |
| `test 0` | 单路在配置下限、上限、1500µs 之间依次过渡，阶段间短暂停留；需先初始化该路 |
| `demo` / `demo 135` | 舵机 0/1/2 同时移动到映射角度，保持 2 秒后返回默认 1500µs |
| `center` | 全部设置 1500µs；如某路标定范围不包含 1500，则使用最近边界 |
| `minall` / `maxall` | 全部设置各自配置的下限或上限，默认为 1000/2300µs |
| `testall` | 已初始化的全部舵机同时测试；需先初始化全部路，仅在供电和机构确认后使用 |
| `stop` | 取消所有运动及测试，关闭可通信通道的 PWM；不切断电源，不保证继续保持位置 |
| `help` | 显示帮助 |

编号必须为 0～23；脉宽必须在该路配置范围内；过渡时间为 0～60000ms，0 表示立即设置。非法参数直接拒绝，不再静默夹到端点。命令格式大小写敏感。

新控制命令会取消自动测试的后续阶段；未被该命令覆盖的其他路平滑运动继续执行。`stop` 才会取消所有路的运动。I2C 写入成功仅代表通信成功，不代表实测到位。`stop` 依赖主控及 I2C 正常工作，异常时应断开舵机电源。

## 修正内容

- 数值在缩窄为 `uint8_t/uint16_t` 前严格检查，防止负脉宽被转成最大值、编号 256 被转成舵机 0。
- 拒绝额外参数、数值尾部垃圾、溢出、NaN/Inf；超长串口行整体丢弃。
- 固定长度接收缓冲，移除 `String/readStringUntil` 等待；运动和测试用 `millis()` 非阻塞执行，可在过程中接收 `stop`。
- 不再把启动时的 1500µs 变量视为已发送位置；停止输出后同样需要重新给初始指令。
- 检查驱动板初始化和 PWM 写入结果，通信失败不更新最后发送值。
- 根据 PCA9685 实际预分频换算 PWM，缓存比例，减少每次脉宽写入前的 I2C 读取。

## 嗡鸣但不转：优先排查

你提供的信息：DS-939MG，电源可能为 5V/3A，是否连接拉线负载尚未确认。

如果是 Corona DS939MG，厂家列出工作电压 4.8V/6.0V、工作电流 200mA/240mA。5V 在该电压范围内；按 200mA 粗算，24 个同时工作已约 4.8A，因此不能认为 3A 电源足够。厂家该页面没有给堵转电流，不能把工作电流当成启动/堵转上限，也不能据此确定最终电源额定电流。应复核电源铭牌，并在舵机动作时测量驱动板 V+ 电压、电流及线缆压降。

原来的 `minall/maxall` 会让所有舵机直接奔向 800/2000µs。对于未标定的舵机和拉线机构，这可能超过机械行程，造成持续用力、嗡鸣、发热而无法继续转动；也可能是多路同时启动引起供电压降。代码不能单独确定是哪一种。PCA9685 发出目标脉冲后会持续输出，所以只发送一次命令也会继续保持，并非只运动一次就停止控制。

先卸载单个舵机，在 1500µs 附近小范围测试：单个正常而多路异常时，优先查供电与配电；卸载后正常而接回拉线后异常时，优先查限位、张力和负载。若单个卸载仍无动作，再查 V+、共地、插头方向、I2C 地址、PWM 信号和舵机本身。持续嗡鸣、发热时停止测试，避免堵转。

默认脉宽范围为 1000～2300µs，单路测试会依次到达两个端点。先用单路脉宽指令逐步确认机械行程，再在 `setup()` 标注处设置各路的 `servos[i].minUs/maxUs`，给机械限位留出余量。

DS939MG 的厂家描述是“单侧脉宽变化 400µs 对应约 40°”，不能默认任意 800～2000µs 范围就是 180°。为兼容原程序，保留 `angle` 命令作为归一化范围映射；调试、标定优先使用 µs。
